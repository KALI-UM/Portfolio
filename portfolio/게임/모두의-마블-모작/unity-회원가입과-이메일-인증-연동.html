Unity 회원가입과 이메일 인증 연동

프로젝트 요약

이메일 인증 API와 Unity 회원가입 UI를 연결했습니다. 인증번호의 유효 시간과 인증 완료 후 가입 가능한 시간을 구분하고, 서버가 거절한 이유를 클라이언트에서 표시하도록 구현했습니다.

항목내용
프로젝트모두의 마블 모작
담당인증 API, Redis 인증 상태 저장, Unity 인증 UI 연동
기술Unity, C#, HTTP, Java, Spring Boot, Redis, JWT

인증번호와 인증 완료 상태 분리

인증번호를 입력하는 단계와 실제 회원가입 요청은 서로 다른 시점에 발생합니다. EmailVerificationStore에서 인증번호와 인증 완료 상태를 별도 키로 저장해 각각의 수명을 관리했습니다.

저장 대상Redis 키 접두사만료 시간
인증번호auth:email:code:5분
인증 완료 여부auth:email:verified:30분

인증번호는 SecureRandom으로 생성한 6자리 문자열입니다. 이미 가입된 이메일에는 발송을 거절하며, 메일 발송이 실패하면 저장한 번호를 삭제하고 실패 응답을 반환합니다.

인증부터 가입까지의 흐름

  1. Unity에서 이메일 인증번호 발송을 요청합니다.
  2. 서버가 중복 이메일 여부를 확인하고 번호를 저장한 뒤 메일을 발송합니다.
  3. 입력한 번호가 저장된 값과 일치하면 번호를 삭제하고 인증 완료 상태를 기록합니다.
  4. 회원가입 요청 시 SignupService가 requireVerified로 인증 완료 여부를 확인합니다.

인증번호가 없거나 만료된 경우, 번호가 일치하지 않는 경우, 인증을 마치지 않은 경우에 서로 다른 오류 메시지를 반환합니다. 인증번호를 확인한 뒤 삭제하는 것과 가입을 허용하는 상태를 기록하는 것을 구분한 구성입니다.

서버 오류를 Unity 화면에 전달하기

서버의 AuthExceptionHandler가 인증 예외를 응답으로 변환하고, Unity의 HttpNetwork와 LoginManager에서 오류 메시지를 반영하도록 연결했습니다. 회원가입과 인증번호 입력 UI를 추가해 발송·인증·가입 요청을 이어갈 수 있도록 했습니다.

성공 여부만 처리하면 사용자는 이메일 중복, 인증번호 만료, 잘못된 번호 입력을 구분하기 어렵습니다. 서버에서 판별한 실패 이유를 UI까지 전달하도록 응답 처리를 보완했습니다.

구현 범위

로그인·로그아웃 구현과 JWT 방식 전환, 플레이어 조회·전적 API, 이메일 인증 API 및 Unity UI 연동을 담당했습니다. 이 글은 그중 이메일 인증과 회원가입 연결에 초점을 맞췄습니다.

인증 상태를 Redis에 저장하고 만료시키는 현재 구현을 설명한 것으로, 발송 제한이나 동시 인증 요청의 원자적 처리까지 완료했다는 의미는 아닙니다.
